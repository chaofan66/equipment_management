## 一、背景与目标

### 1.1 背景
当前系统的维保业务逻辑（`backend/src/data/maintenance.js`）采用**粗粒度全量生成**：按设备类别编码前缀（02/05/06/08→A类2次，其余→B类1次）为所有设备统一生成计划，一级/二级保养共用同一套5个通用工序，审批统一为"待执行→进行中→待验收→已完成/已超期"。

Excel 试验版展示了曲四车间完整的目标维保体系，其核心思想是**"设备类别 → 标准模板 → 设备台账 → 项目实例 → 审批归档"**的层级结构，当前系统缺失了标准模板这一层。

### 1.2 三个方向决策
| 决策项 | 结论 |
|--------|------|
| 项目分配模式 | **标准文件驱动**：日常点检/一级保养/二级保养/设备润滑/定期检查五类执行表单，仅在设备小类配置了对应标准文件后才生成；**保养计划＝「一级保养计划」「二级保养计划」「设备润滑计划」三个 tab，各 tab 均为 设备×12月 可勾选网格，级别由 tab 决定（一级 tab 勾选即排一级、二级 tab 勾选即排二级、润滑 tab 勾选即排润滑），网格仅列配对应标准（03/04/05）的设备，与资产分类无关** |
| 保养执行入口 | **「一级保养」「二级保养」「设备润滑」三个 tab**（维保管理子导航，`LevelTaskView` 共用，级别由路由 meta 决定）作为对应级别已排期任务列表执行视图：按 年份+月份（默认当月）+车间 筛选，点行打开处理抽屉逐步执行；与保养计划网格点格子处理并存 |
| 标准文件形态 | **结构化模板库**：按6位小类维护检查项/工序/合格标准/工器具/安全告知等结构化数据（fileCode 01/02/03/04/05/06），直接驱动表单生成；未配置的小类不生成 |

## 二、现状分析（当前系统）

### 2.1 后端数据层 `backend/src/data/maintenance.js`
- `maintenancePlans`：按类别前缀为每台设备生成1-2个计划，字段含 `category`(A/B)、`level`(一级/二级)、5个通用 `processes`、5条固定 `safetyNotice`、3个签字字段
- `DAILY_CHECK_ITEMS`：按类别前缀(通用/02/04/03/00/06/05)的日常点检项
- `lubricationCards/Orders`、`oilTestReports`、`wasteOilRecords`：润滑
- `inspectionRecords`、`rectificationItems`：定期检查与整改跟踪
- `workOrders`：维修工单（简化安全字段）

### 2.2 前端页面 `frontend/src/views/maintenance/`
维保管理子标签：维保总览 / 保养计划 / 日常点检 / 一级保养 / 二级保养 / 设备润滑 / 定期检查 / 维修工单 / 设备培训 / 标准文件配置 / 设备分配（页内「车间 / 维保」两个子 tab）。
说明：「设备分配」为设备逐级分配 tab（车间分配 + 维保分配，页内两个子 tab）；「一级保养」「二级保养」「设备润滑」共用 `LevelTaskView` 执行页。

### 2.3 关键缺口
标准文件(`FileConfigView`)只做**附件上传绑定**，不结构化、不进业务逻辑 —— 这是与 Excel 最大的结构性差异。

## 三、Excel 目标业务逻辑梳理

### 3.1 三层架构
```
① 标准文件库(按6位小类编码)           ← 02010101~02010106
   020101通用桥式起重机 = {安全规程, 日常点检标准, 一级保养标准, 二级保养标准, 设备润滑标准, 定期检查标准}

② 设备台账 + 维保总体流程              ← 设备台账 / 维保总体流程
   每台设备：资产分类(标准模板定位与台账分组) + 10个职责角色 + 车间归属
   保养计划(一级/二级/润滑)由用户按车间在对应保养计划 tab 的设备×12月网格勾选月份创建（级别由 tab 决定），不按资产分类排期

③ 各项目执行 sheet                    ← 日常点检/一级保养/二级保养/设备润滑/定期检查
   每张表 = 标准模板内容 + 实例 + 审批链流转
```

### 3.2 各项目类型与周期（维保总体流程 sheet）
> 完整审批链与角色绑定见 **§3.6**（以各表单 sheet 时间步序为权威；本表仅列周期概览）。
| 项目 | 周期/生成方式 |
|------|----------------|
| 日常点检 | 每天（配 02 点检标准的设备每天自动出单，全量） |
| 一级保养 | **用户自定义**：一级保养计划 tab 网格勾选月份（设备配 03 标准）；执行入口＝「一级保养」tab |
| 二级保养 | **用户自定义**：二级保养计划 tab 网格勾选月份（设备配 04 标准）；执行入口＝「二级保养」tab |
| 设备润滑 | **用户自定义**：设备润滑计划 tab 网格勾选月份（设备配 05 标准）；执行入口＝「设备润滑」tab |
| 定期检查 | 随时（手动「发起检查」，配 06 标准；不按资产分类频率自动排期） |
| 设备培训 | 每月（培训活动粒度） |
| 设备维修 | 随时（独立 6 步流程：报修→指派含安全审核→接单→完工提交→完工确认→完工审核自动归档，无标准门禁） |

> **注**：日常点检频率统一为**每天**（全量，配 02 标准即每天出单），不再按资产分类区分 每周/每月；"日常巡检"独立项目不实施。

### 3.4 标准模板内容（以020101为例）
| 模板 | 结构 | 字段 |
|------|------|------|
| 安全操作规程 | 章节式 | 适用范围/人员资质/劳动防护/安全风险/操作要求 |
| 日常点检标准 | 15项 | 项目+检查保养内容 |
| 一级保养标准 | 14项 | 项目+工序内容+合格标准 |
| 二级保养标准 | 15项 | 项目+工序内容+**方式方法+工器具**+合格标准要求 |
| 设备润滑标准 | 同 03 | 项目+工序内容+合格标准 |
| 定期检标准 | 5类 | 钢结构/机械/液压/电气/安全装置 + 达标/超标 + 问题处理意见 |

> **注意**：020101（通用桥式起重机）仅是**标准模板库中的一个实例**。模板编码 = 资产类别编码(6位) + 文件类型码(2位)，如 `02010103` = (020101, 一级保养标准)。系统需按此机制设计，覆盖全部分类（详见 §5.7 标准模板库设计）。**模板具体内容（章节/项/类/表头列名）纯由业务上传标准文件 Excel 生成**——上传解析不设死规则（列名「精确→包含→按列序兜底」，§5.7(2)）；**02-06 五类标准 Excel 主 sheet 含「安全告知及注意事项」行（表头前，标签+相邻单元格多行文本）自动带出 `safetyNotice{title,content}`，无则内容微调手动填文字（无文件上传），执行表单顶部展示**。

### 3.5 职责信息 = 角色操作权限矩阵（设备台账 sheet，权威）

设备台账**"职责信息"模块**（列46-55）定义**每个角色可执行的工作流步骤（操作权限）**：
- 10 列：操作人员 / 操作班长 / 操作主管 / 车间主任 / 维保人员 / 维保班长 / 维保主管 / 维保主任 / 维保归档 / 查看权限
- 每列填 `stepN:动作`，**step 编号与该设备所属项目的表单步序一致**（表单 sheet 为权威步序），表示该角色被授权执行该步骤

**从设备台账逐行提取验证（职责信息 ↔ 表单步序对齐）：**

| 设备 | 项目 | 操作人员 | 操作班长 | 操作主管 | 车间主任 | 维保人员 | 维保班长 | 维保主管 | 维保主任 | 归档(自动) |
|------|------|---------|---------|---------|---------|---------|---------|---------|---------|---------|
| ...01 | 日常点检 | ①提交 | | ③确认 | | | | | | 自动 |
| ...03 | 一级保养 | ①提交 | ②验收 | ③确认 | | | | | | 自动 |
| ...04 | 二级保养 | | ②验收 | | ③确认 | | ①提交 | | ④审核 | 自动 |
| ...05 | 设备润滑 | | ②验收 | | ③确认 | | ①提交 | | ④审核 | 自动 |
| ...06 | 定期检查 | ②确认 | | | | ①提交 | | ③验收 | ④审核 | 自动 |
| 培训 | 设备培训 | ①提交 | ①提交 | ②确认 | | | | | | 自动 |

> **注**：各项目「归档」步均**自动完成**——日常点检/一二级保养/设备润滑/定期检查/设备培训在上一步校核通过即自动归档；设备维修在「完工审核」通过即自动归档。

> **结论**：step 编号是**每个项目表单内的局部步序（1..N）**，职责信息用 `stepN` 表达"哪个角色授权操作哪一步"，即 **角色 → 步骤权限矩阵**。设计上作为**权限控制**依据：计划处于第 N 步时，仅被该设备职责信息授权的角色可执行。
> 维保总体流程 sheet 是简化版角色视图；**以设备台账职责信息为准**（更完整，含操作班长/车间主任/维保班长/维保主任）。

### 3.6 维保全流程总览（端到端）

> **关键认知：Excel 里维保流程存在两个视图，需合并理解。**
> - **视图A·时间步序**：各**表单 sheet** 显示的执行先后顺序 —— **权威依据**
> - **视图B·角色绑定**：`维保总体流程` sheet 的 step 编号绑定的是"角色列"，**非时间顺序**
> - 两视图编号在 Excel 内部有出入（如定期检查在Bc显示4步、Ax显示5步），**系统实现以表单时间步序为准定义步骤引擎，用总体流程绑定各步角色**

**C. 端到端生命周期**
```

  → 各项目执行与审批(见 A/B)：
      日常点检(每天) ──异常→ 停机 + 一键报修→维修工单（独立流程）
      一级/二级保养、设备润滑(网格勾选月份)

      设备培训(每月) ──内容=安全操作规程──
      设备维修(随时) ──紧急可先施工、24h内补流程──
  → 归档
  → 报表自动汇总：日常点检月报(完好率/利用率/故障率) + 维修记录汇总 + 定期检查问题汇总 + 各项目完成率
```

**D. 跨模块联动规则**
1. **日常点检异常** → 立即停机 + 一键生成维修工单，点检问题反馈随单记录（工单带 `sourceId=点检单`）；**维修完工归档时回写**点检异常项为"已处理"，点检报表只统计未处理异常（§5.10 问题2）
2. **定期检查发现问题** → 按处理意见分流：停机处理/计划维修(转维修工单) / 监控运行(进整改跟踪 rectificationItems 闭环)；**整改闭环**：整改人(维保人员)+整改期限(默认15天可配)+复查(下次定期检查或专项复查)，完成→关闭，超期→催办（§5.10 问题7）
3. **设备培训内容复用安全操作规程**（fileCode 01），培训即规程考核
4. **完工/归档** → 自动汇总入 三大报表 与各项目完成率

### 5.1 核心数据模型（新增/重构）

> **🔒 基础数据只读原则（硬约束，用户确认）**
> **设备台账（devices.js 4588台·40字段）、部门车间字典（WORKSHOP_DEPT_MAP / DEPT_CODE_MAP / WORKSHOP_CODE_MAP / DEPT_WORKSHOP_TREE）、资产类型树（DEVICE_TYPE_TREE / TYPE_CODE_MAP）为存量基础数据，本轮调整零改动**——不改值、不覆盖、不删除、不重排。
> - 台账**已有** `assetCategory`（A/B/CT/C1/C2，4588台全有值）、`typeCode`(6位小类)、`type`(大类/中类/小类路径)、`person`(负责人姓名)、`area`(车间文本) → **只读引用**，维保逻辑从这些字段推导，不写回
> - Excel 更细的资产分类（Ac/Ax/Bc/Bx/C1c/C1x）、10角色人员、参与项目、步骤权限 → 全部落**新增配置侧**（§5.9(2) 映射表、§5.8 绑定记录、projects 配置），运行时与台账只读数据**合成展示**（派生缓存）
> - **全量设备生效**（无试点范围限定）；`area` 等台账字段仅只读引用
> - 模板库复用 `DEVICE_TYPE_TREE` 结构与 `STANDARD_FILES`(01~06) 只读参照，**不改树结构、不删改现有标准文件**，仅新增配置（模板库、assetClassMap）
> - 部门/车间字典只读引用：职责绑定分层 scope 用**车间编码**引用，不新增字段到字典

```

  ├─ assetClass           派生资产分类（Ac/Bc/Ax/Bx/CT/C1c/C1x/C2...，§5.9(2) 映射推导；不覆盖台账 assetCategory）
  ├─ personnel            10职责角色人员 {操作人员, 操作班长, 操作主管, 车间主任,

维保实例(Plan/Record) 增加字段:
  ├─ projectType          项目类型(决定审批链步骤，§5.2)
  ├─ templateId           生成时解析到的模板主键(设备typeCode + fileCode)
  ├─ templateVersion      模板版本号(快照依据)
  ├─ items[]              从模板复制的执行项快照(点检/一二级保养/润滑) 或 categories[]快照(定期检查)
```

> **检查记录**（定期检查）：`POST /maintenance/inspections` 发起时初始化——**检查编号 = yyyy+mmdd+6位流水号**（如 `20260812000001`，当日全局递增、无资产编号无分割线，V1.61）；字段含 `categories[]`（检查项目表，含 result 达标/超标）/`issues[]`（发现问题行，含 desc/images[]/opinion）/`safetyNotice{title,content}`；`steps[]`（5 步：提交/确认/验收/审核/归档，各步 role/signatures[]/status/date）与 `rejectLog[]`；状态由 steps 派生（待提交/待确认/待验收/待审核/已归档；**归档步自动完成，审核通过即自动归档**）；步骤流转 `PUT /maintenance/inspections/:id/step/:stepNo`（角色门禁 + 乐观锁 version + 驳回退回「提交」重提），见 §5.2 步骤引擎。`GET /maintenance/inspections` 每条含 `deviceType` = 台账设备 `type`「大类/中类/小类」；提交时对每个含 desc 的问题**自动生成整改项**（进行中，期限=检查日期+15天），与整改跟踪联动（§5.6 定期检查问题汇总）。

> 配置侧 `deviceConfig.personnel`（派生缓存，非台账字段）为**按系统角色派生的解析结果快照**（`personnel.roleId === roleKey` 的人，§5.8(3)，非手工录入）。**注意**：实例的 `personnel` 快照仅作**已签留痕展示**（当时谁签）；**待签步骤的可执行人按系统角色实时解析**（`roleId === step.role`，§5.8(4)），两者解耦（§5.10 问题1）。

### 5.2 审批工作流引擎
- 用**步骤引擎**替代单一 status：每项目类型定义 steps 模板，实例记录当前进度
- **步序以各表单 sheet 为权威**（§3.6A），**各步角色绑定来自维保总体流程**（§3.6B），Excel 内部两视图编号不一致时以此口径统一：

| 项目 | 时间步序 | 步数 |
|------|---------|------|
| 日常点检 | 提交(班前)→提交(班后)→确认→归档 | 4 |
| 一级保养 | 提交→验收→确认→归档 | 4 |
| 二级保养 | 提交→验收→确认→审核→归档 | 5 |
| 设备润滑 | 提交→验收→确认→审核→归档 | 5 |
| 定期检查 | 提交→确认→验收(校核)→审核(校核)→归档 | 5 |
| 设备培训 | 提交→确认→归档 | 3 |
| 设备维修 | 报修(自动完成)→指派(含安全审核)→接单(施工准备)→完工提交→完工确认→完工审核(自动归档) | 6 |

- 每步绑定设备级角色（操作人员/操作班长/操作主管/车间主任/维保人员/维保班长/维保主管/维保主任，归档自动完成），签名后进入下一步
- **步骤级权限控制**：计划处于第 N 步时，仅被该设备**职责信息（stepPermissions）**授权的角色可执行该步（依据 §3.5），其余角色只读/不可操作
- 超期规则：一级/二级保养、设备润滑按**标准文件执行月份整月**判定（§5.2/§5.4，超过该月月末 `periodUntil` 快照未完成置「已超期」并锁定，系统管理员可越过）；日常点检按日+1天宽限期；定期检查/设备培训按+7天宽限期
- **驳回/退回**：审批步（确认/验收/审核）不通过 → 填写驳回原因，实例**退回上一步执行步**（点检退回"班后提交"、保养退回"提交"、维修按当前步退回）；状态=待重提，重新提交后重走该步及下游
- **改期/作废**：实例支持"改期"（需审批、留痕，按新 planDate 重排）与"作废"（需审批、留痕，作废从完成率分子剔除但计入计划数）
- **双轨兼容**：旧 plans(status) 与新实例(steps[]) 同路由共存；全量生效后 V2 新逻辑覆盖全部设备，旧 plans 保留只读不参与生成
- **并发控制**：步骤流转接口加乐观锁（version），冲突返回 409 提示刷新；单实例操作原子化

### 5.3 标准模板 → 项目实例 分配链路（点检/一级/二级/润滑/定期检查）

> 本节把"模板库 → 设备 → 各项目执行实例"的**分配链路**补完整，明确：**模板决定内容、项目类型决定流程、实例 = 两者+人员的快照**。分工边界与术语澄清见 (6)。

#### (1) 链路总览（6步）
```
设备台账(含 typeCode / 资产分类 / projects[] / 车间)
  │ ① 模板解析
  ▼
标准模板库(§5.7) 按 设备typeCode(6位小类) 解析对应模板
  (点检=02 / 一级=03 / 二级=04 / 润滑=05 / 定期=06)，未配置不生成
  │ ② 生成方式
  ▼
日常点检 = 每天全量惰性生成；定期检查 = 不自动排期、手动「发起检查」；
一级/二级保养、设备润滑 = 由用户通过「保养计划」对应 tab 设备×12月网格勾选月份创建（不自动排期）
  │ ③ 实例生成
  ▼
项目实例(Plan) = 模板items快照 + 审批链steps + 设备人员快照
  │ ④⑤
  ▼
执行流转(§5.2 步骤引擎) → 归档 → 报表/异常联动(§5.6 / §3.6D)
```

#### (2) ①模板解析（"对应模板"如何定位）
- 每台设备有 `typeCode`(6位小类，如020101)；对每个项目取该项目 `fileCode`（§5.7(5) 映射：点检=02、一级=03、二级=04、润滑=05、定期=06）
- 按 `(设备typeCode, fileCode)` **小类直读**解析模板（无继承、无全局兜底，§5.7(2)）
- 解析结果含 `生效来源`（自定义 / 未配置），实例记录 templateId + templateVersion

#### (3) ②生成方式
- **一级/二级保养、设备润滑不再自动排期**：由用户通过「保养计划」（§六 F1）在 **一级保养计划 / 二级保养计划 / 设备润滑计划 三个 tab** 的 **设备×12月 网格** 中勾选月份——一行一台设备（资产台账基本信息：设备编号/名称/资产分类/车间 + 保养级别标注），列为一至十二月勾选格。
  - **级别由 tab 决定**：一级保养计划 tab 勾选某月 → 生成该设备该月**一级保养**；二级保养计划 tab → **二级保养**；设备润滑计划 tab → **设备润滑**。网格仅列出配对应标准文件的小类设备（一级 tab=配 03 标准，二级 tab=配 04 标准，润滑 tab=配 05 标准），未配该级别标准的不出现。
  - **勾选某月 = 该设备该月保养 1 次**，生成 planDate = 所选月份 1 日；例：某设备在 一级 tab 勾选 2月+4月 → 该设备在 2月、4月 各做一次一级保养；同一设备可在不同 tab 分别排一级/二级/润滑保养。
  - **勾选仅确定保养月份**：已有保养单的月份显示已勾选、不可取消；取消勾选已生成月份 = 作废该月保养单。
  - **按资产类别批量处理**：网格支持按**资产类别（大类/中类/小类）级联筛选**收窄行（车间内本地过滤）；「**一键整类排期**」将选中类别（当前车间、配当前 tab 标准）设备的所选月份批量勾选进草稿，**跳过已有保养单的月份与过去的月份**，核对后经「保存计划」一次批量生成。
  - **执行入口**：维保管理新增「一级保养」「二级保养」「设备润滑」三个 tab（`LevelTaskView` 共用），展示对应级别已排期任务（本网格勾选月份→保存生成的单据），按 年份+月份（默认当月）+车间 筛选，点「处理」打开执行抽屉逐级提交（一级=提交→验收→确认→归档 / 二级·润滑=提交→验收→确认→审核→归档）；与「点网格已有保养单格子打开处理抽屉」并存。
  - **执行与完成均由用户自定义**，系统不按资产分类自动排期、不自动判定完成。
- **定期检查**：**不自动排期**，由用户在「定期检查」tab 手动「发起检查」（配 06 标准才可发起，未配置提示「没有配置定期检查文件」）；发起即进入审批流（提交→确认→验收→审核→归档，§5.2）。
- 日常点检 = 每天惰性生成（见下）。
- 实例 planDate = 排期日 / 选月 1 日；超期判定见 §5.2（一级/二级/润滑按执行月份整月、点检按日+宽限、定期检查+7天）

#### (4) ③惰性生成（日常点检全量每天）
- **日常点检全量每天**：所有**配置了 02 点检标准**的小类设备，每天自动生成当日点检单（不再按资产分类区分 每周/每月；C2 等未配置小类不生成）
- **日历口径**：按日历日逐日生成（周末/法定节假日也生成），**一设备一日一张点检单**（班前/班后两次提交，不按班次拆单）；多班组轮班设备允许多人依次提交，实例记 `shift` 字段追溯
- **触发机制**：读取当日点检即**惰性生成**（打开页面即有当日单），手动"补生成"入口兜底
- 报表跨月聚合按日实例累计（§5.6 点检月报）

| 设备润滑 | 05 设备润滑标准 | items[] 同 03（含 **checked**）+ safetyNotice | 5步(提交→验收→确认→审核→归档) | 用户自定义（润滑计划网格勾选月份） |
| 定期检查 | 06 定期检查标准 | categories[]（每类检查项+达标/超标）+ 处理意见 | 5步(提交→确认→验收→审核→归档) | 手动发起（不按资产分类频率排期） |

- **内容固化（快照）**：生成时把模板 items/categories/safetyNotice **整体复制进实例**（§5.7(4)），后续模板改动不影响进行中实例；新实例用最新版
- **表头快照**：生成时把模板 `labels`（各语义列真实列名，§5.7(3)）一并复制进 `plan.labels`，实例表头随单展示、与上传 Excel 表头一致
- **定期检查实例**：一份单含 06 模板全部 categories（钢结构/机械/液压/电气/安全装置），按类分区展示、逐类记录 达标/超标+问题描述+处理意见；问题自动汇入"定期检查问题汇总"报表，处理意见(停机/计划维修/监控运行)按 §3.6D 分流
- **执行结果与单据结构（定稿口径）**
  - **点检单结构**：一张单两区块——区块A 班前检查（按02班前模板 items 逐项，三态：正常/异常/停工，三独立打勾列，选中样式为勾选——正常绿✓/异常橙✓/停工红✓，仍单选，「今日点检」列表「状态」列按状态着色：待执行橙/进行中蓝/已超期红/已归档绿）；区块B 班后固定表单（说明「每日下班填写每日设备运行信息。」+ 3 行录入：每日运行时间/故障停台时间/计划停台时间，§5.9(3)，不生成班后检查项）。任一项"异常"→ 提示停机+一键报修，仍允许提交，由确认人判是否通过
  - **弹框展示**：日常点检弹框记录表头信息区（资产编号/资产名称/使用部门/资产分类/规格型号）+ 说明1（班前检查保养在每班生产前20分钟内进行，发现异常立即报告生产保障维修人员。）+ 流程步骤；**步骤已提交内容在当前提交界面累积展示**——当前步骤录入表单+提交按钮**上方按序堆叠全部已提交步骤内容（只读）+其下提交人信息（姓名/工号/职务/提交时间）**，顶部流程步骤纯状态展示（不可点击）；只读内容 daily step1=items 三态只读表（勾选样式）、daily step2=台时 3 项、level1/2/lubrication step1=执行项只读表（「保养」勾选态）、periodic step1=逐类只读表（达标/超标+问题描述+处理意见），无表单步仅显示提交人信息；提交人取当前登录人；**提交本步/驳回退回按钮固定弹框底部**（el-drawer `#footer` 固定区，不随内容滚动、始终可视），归档提示「本单已归档 ✅」同步置底；**level1/level2/lubrication 执行项目表格上方新增记录信息块**（资产编号/资产名称/使用部门/资产分类/规格型号，与日常点检同样式）
  - **点检时间窗**：班前区块建议设备班前提交，不强制锁死时间窗，超时允许补录并留痕
  - **点检缺检**：当日未完成 → 次日记"昨日缺检"红标并允许补录，计入当月完成率分母
  - **一/二级保养**：每项记录"完成/异常+处理说明"；异常项不得进入下一步（由验收/确认人判放行或驳回）
  - **一级/二级/润滑执行结果**：提交人**逐项勾选**本次实际执行的保养项（勾选=已保养，列头「保养」）；验收人核对勾选情况，未勾选项视为本次未执行，可走 §5.2 驳回
  - **定期检查**：每类记录"达标/超标+问题描述+处理意见"（停机/计划维修/监控运行），问题自动汇入"问题汇总"报表并按 §3.6D 分流
  - **培训（按培训活动为粒度）**：一次"培训活动"覆盖多台设备 + 参训名单，发起人提交、确认人确认（§5.2 3步）；设备台账侧只读关联其所属活动，避免"每设备每月一条"冗余；内容复用安全规程

### 5.4 KPI 计算（日常点检-报表；对齐 PRD §7.3.1）
- **设备完好率** = 完好天数 / 当月天数（完好日 = 当日有班后记录且故障停台=0 且当日无未处理维修工单，§5.10 问题4）
- **设备利用率** = 运行台时 / (运行台时 + 故障停台 + 计划停台)（即 ΣR ÷ Σ(R+F+P)；分母为 0 记 0%）
- **设备故障率** = 故障停台时间 / 运行台时（运行台时为 0 记 0%）
- **计划停运率** = 计划停台时间 / 运行台时（V1.59 替代原随机故障率；运行台时为 0 记 0%）
- **不再使用额定日工作时长 / 额定台时**；利用率不以「当月天数 × 额定台时」为分母
- 月度**取数周期 = 设备 02 模板该执行月整月（V1.57 起为自然月整月，月末日由月份推导）**，每日记录 运行台时/故障停台时间/计划停台时间
- 台时数据来源见 §5.9(3)：班后固定表单人工录 每日运行时间/故障停台时间/计划停台时间 3 项；计划停台**手工填写**（有排期仅提示，不自动带入）
- **总体 KPI**：总体利用率 = 全部设备 ΣR ÷ 全部设备 Σ(R+F+P)；总体完好率 / 故障率 / 计划停运率按参与设备（当月配 02 标准）汇总

### 5.5 维修工单安全流程（6 步）
- **① 报修**（报修人=当前登录人）：表单按《设备报修第一步.jpg》——设备信息区（**资产编号/资产名称/使用部门/资产分类/规格型号**，选设备自动带出）+ **故障情况/维修需求描述** + **紧急程度**（普通/紧急）+ 报修人（只读）；**工单号 = yyyy+mmdd+6位流水号**（如 `20260812000001`，当日全局递增、与定期检查检查编号同格式，V1.61）；报修提交即自动完成「报修」步进入「指派」。
- **② 指派（含安全审核）**：**维保主管（mtSupervisor）** 把报修单指派给对应**维保人员（mtPersonnel）**，选人即审批放行（安全审核并入本步，不设独立审批点）；**强绑定**——后续「接单」「完工提交」仅被指派的维保人员可提交（他人提交 403 / 前端按钮禁用）。
- **③ 接单（施工准备）**（维保人员，提交）：表单按《维保接单表单.jpg》——**现场施工准备** 4 项勾选：已告知同区域/同轨道相关操作人员维修作业；设备已完全停止运行、能量已隔离（断电/挂牌）；维修区域已设置警示带/标识；高空作业、动火作业、有限空间等危险作业！；**危险作业票号1-4**（至多4张）+ **安全交底**（已了解现场风险及采取相应防护措施）。安全确认以本步交底留档。
- **④ 完工提交**（维保人员，提交）：表单按《维保完工提交内容.jpg》——**开始时间/完成时间**、**维修内容**、**更换备件**、**故障原因**（正常磨损·寿命到期）、**停台类型**（随机故障）、**试车情况**（空载正常）、**异常描述**。
- **⑤ 完工确认**（操作主管，使用方验收）：确认维修完成且试车正常。
- **⑥ 完工审核（通过即自动归档）**：**维保主任（mtDirector）** 审核通过即自动归档，状态派生「已归档」，点检异常回写随最后一步触发。
- **紧急维修**：可先施工，24小时内补全流程。

### 5.6 报表与统计输出层（设备维保记录汇总 / 定期检查问题汇总 / 日常点检-报表）

Excel 最后3个 sheet + 设备台账列58-60（项目/月度报表1/统计报表2）共同定义**按项目类型的报表输出体系**，报表均由各项目执行实例**数据自动汇总生成**，非手工录入。

**报表矩阵（每项目类型配"明细报表 + 统计指标"双视图）：**

| 项目类型 | 明细/月度报表 | 统计指标 |
|---------|-------------|---------|
| 日常点检 | 日常点检月度报表（每设备一张） | 总体设备完好率、总体设备利用率 |
| 一级保养 | 一级保养报表（月度汇总 KPI + 明细表） | 一级保养完成率 |
| 二级保养 | 二级保养报表（月度汇总 KPI + 明细表） | 二级保养完成率 |
| 设备润滑 | 设备润滑报表（月度汇总 KPI + 明细表） | 设备润滑完成率 |
| 定期检查 | 定期检查报表 + **定期检查问题汇总** | 定期检查完成率 |
| 设备维修 | **设备维保记录汇总** | — |
| 设备培训 | 培训记录 | — |

**一级/二级保养、设备润滑月度报表（月度汇总 KPI + 明细表）：**
- **入口**：「一级保养」「二级保养」「设备润滑」三个执行页（`LevelTaskView`）内「**月度报表**」子标签（radio：保养列表 / 月度报表）。
- **保养列表 tab**：无统计卡，顶部 年份+月份+**搜索（资产名称/编号合并）**+**资产类型级联**+车间+**状态** 筛选（V1.62 统一；状态=全部/待执行/进行中/已超期/已归档/已顺延/已作废，搜索/资产类型/状态**仅过滤列表，月度报表不受影响**）；明细表列：设备编号/设备名称/资产类型/资产类别/使用部门/规格型号/开始执行时间/结束执行时间/状态着色/操作（V1.62 去「车间」列、加 资产类型/使用部门/规格型号 列）。
- **月度报表 tab 形态**：选年月（+车间）→ **月度汇总 + 明细表**——KPI 卡片（**计划数/已归档/待执行/进行中/已超期 5 卡 + 完成率** el-progress 圆环）；明细表每行一张保养单（设备编号/名称/资产类别/车间/计划日期/当前步骤/状态着色 + **保养项完成率** = 已勾选保养项数 ÷ 总保养项数）。**取数按 年月+车间 自然月聚合**（一级/二级/润滑**非每日检查（一个月几次）**，月度报表不再对齐日常点检逐日网格）。
- **口径**：**计划完成率 = 当月已归档数 ÷ 当月计划数**（作废计入分母不计分子，沿用 §5.6；计划数=当月全部计划含作废）；**保养项完成率**为执行层面逐项勾选比例（数据源 `checked`）。按「**计划月**」统计（当月应做/完成），与年度「各项目完成率」（按实际归档月）**并存、用途不同**。
- **数据来源**：复用 `GET /v2-plans?projectType&year&month` 列表实例 items/steps/status，**前端聚合，后端零改动**。

**三大报表明细结构（Excel 提供模板的3张）：**

1. **日常点检-报表**（单设备月度）
   - 编号 = 设备编号+年份+月份；**取数周期 = 设备 02 模板该执行月整月（V1.57 起为自然月整月）**；网格 = 点检项×日
   - 台时记录：每日运行时间 / 故障停台时间 / 计划停台时间
   - 自动计算：当月天数 / 设备完好率 / 设备利用率（ΣR÷Σ(R+F+P)） / 设备故障率 / 计划停运率（**无额定台时**，对齐 PRD §7.3.1）
   - 签字：操作人员、操作主管

2. **设备维保记录汇总**（维修月度汇总，20行）
   - 工单号 = yyyy+mmdd+6位流水号：`yyyymmdd-6位序号`（如 `20260812000001`，当日全局递增，V1.61）
   - 列：停台统计(开始/结束/停台时间/停台类型) + 修理情况(维修内容/更换备件/故障原因/维保人员) + 安保情况(安全交底/危险作业票1-3)
   - 数据来源：维修工单完工后自动汇总；**维保人员 = 指派维保人员**（`repairData.assigneeName`）

3. **定期检查问题汇总**（问题跟踪报表，20行）
   - 列：定期检查单号 / 资产信息 / 发现问题 / 处理意见
   - 数据来源：定期检查(inspectionRecords)发现问题 → 自动汇总，与整改跟踪(rectificationItems)联动
   - 落地到定期检查页「**月度报表**」子标签——**自然月**取数：选月份 → 仅列出**有发现问题**的检查记录（有问题记录数 + 明细：检查编号/设备/部门/日期/检查人/问题数/发现问题/处理意见）；**不再**生成整改项，**不设**已关闭/整改中/已超期/待整改状态。纯前端聚合 `GET /inspections`。

**对系统的含义：**
- 报表全部**自动生成**，从各项目执行实例聚合
- 每项目类型 = 明细报表 + 统计口径（完成率 / 完好率 / 利用率 / 故障率）双视图
- 报表落地各执行页：日常点检月报（日常点检页）/ 一级·二级·润滑月度报表（LevelTaskView）/ 定期检查问题汇总（定期检查页月度报表）
- 完成率口径：按**实际归档月**统计（当月归档数 ÷ 当月应计划数）；未按时归档计入原计划月"超期未完成"；作废实例从分子剔除但计入计划数（§5.2）；一级/二级保养、设备润滑**月度报表**完成率按「**计划月**」口径（当月已归档 ÷ 当月应计划数），与年度「各项目完成率」（按实际归档月）**并存、用途不同**
- 报表页支持导出 Excel/PDF（对齐 Excel 打印版式）
- **取数周期（§5.10 问题5）**：日常点检月报按设备 02 模板该执行月整月；一级/二级/润滑月度报表按自然月（年月+车间）；维修汇总/问题汇总按自然月；完成率按自然月归档，各表标注取数边界

### 5.7 标准模板库设计（核心扩展机制）

模板以**6位小类为单位**维护（`standardTemplates[typeCode][fileCode]`），**无继承、无全局兜底**；**未配置模板的小类不生成任何维保实例**（"分配了标准才有执行表单"）；模板编码 = 小类编码 + 2位文件类型码（如 02010103）。内容**纯由业务上传标准文件 Excel 后生效**（代码不内置任何默认模板）。

#### (1) 模板主键与注册
- 模板 = `(typeCode 6位小类, fileCode 标准类型)` 唯一确定一套模板内容
- 模板编码格式：`资产类别编码 + 文件类型码`（与 Excel 的 02010103 一致）
- 注册范围覆盖整个 `DEVICE_TYPE_TREE`（11大类全部小类节点），复用 `backend/src/data/dict.js` 现有类别树
- 未配置模板的小类不生成实例，不必提前配齐

#### (2) 解析规则
- 模板以 **6位小类** 为单位直读：`standardTemplates[typeCode][fileCode]`
- **未配置模板的小类不生成维保实例**（"分配了标准才有执行表单"）；不继承中类/大类、无全局默认兜底，避免"未分配却自动出单"
- UI 标注"生效来源"：`020101 自定义 / 未配置`
- 示例：门吊(020107) 未配置模板 → 其下设备不生成任何维保表单；业务按需上传标准文件 Excel 后即生效
- **表头捕获**：表头行探测定位后，把各语义列**真实列名**存模板 `labels`（见 (3) schema）——解析列名 ≠ 固定文案，系统三处展示按 `labels` 动态表头对齐上传 Excel；**无 labels 时表头留空**；**列名解析放宽（不设死规则）**——语义列探测「精确 → 包含 → 按列序兜底」：项目/类别/部位 任一 = item 列，任何含「内容」的列 = 内容列（工序内容/检查保养内容/检查内容…），含「标准」的列 = 标准列（合格标准/判定标准…），含「方法」/「工具」= 方式方法/工器具；匹配不上时跳过「序号」列按列序兜底（第 1 数据列 = 项目、第 2 = 内容），任意 ≥2 数据列的 Excel 均可上传；仅列数不足时提示「未识别到 XX 列，请确认首行为表头」

### 5.8 职责信息→账号绑定与10角色配置

> 目标：把设备台账"职责信息"的 **10 个职责角色从"文字/姓名"落到系统账号（personnelId）**，使步骤引擎能按"当前登录账号"做设备级、步骤级权限控制。

#### (1) 现状缺口与角色即职责模型
| 维度 | 现状 | 目标 |
|------|------|------|
| 设备负责人 | `person` 自由文本姓名，未关联账号 | 关联 `personnelId`，姓名由人员表带出；**台账 `person` 字段保留不覆盖**，仅作初始占位展示 |
| 账号源 | `backend/src/data/auth.js` 的 `PERSONNEL`（16人）：`{id, employeeId, name, dept, roleId}` | 复用为账号基座，未来可接真实账号体系（工号/LDAP/CIMS） |
| 权限粒度 | 系统角色 roleId（5个）只控菜单级，且未真正鉴权 | **系统角色即职责**（11 个 = 10 职责 + 系统管理员）：既控菜单级（系统操作权限），又控设备级步骤（`roleId === step.role`） |
| 登录态 | 内存单例 `CURRENT_USER`（有 personnelId） | 以 personnelId 作为权限判定锚点 |

> **角色即职责模型（关键设计）**
> - **系统角色 roleId**（admin 系统管理员 + 10 职责 operator/opLeader/opSupervisor/workshopDirector/mtPersonnel/mtLeader/mtSupervisor/mtDirector/archiver/viewer）：**既控菜单级权限（系统操作权限，§5.8(7)），又控设备级步骤执行（`roleId === step.role`，§5.8(4)）**
> - 每名人员**唯一系统角色**（`personnel.roleId`）；步骤引擎可执行人按系统角色全局派生，无独立"职责绑定"（§5.8(3)）

#### (2) 10职责角色字典（roleKey 复用 §3.5）
| roleKey | 角色名 | 基数 | 默认归属层级 | 说明 |
|---------|--------|------|-------------|------|
| operator | 操作人员 | 1:N | 设备级 | 每台设备的操作工，可多人 |
| opLeader | 操作班长 | 1:1 | 班组级（操作班组） | 设备所属操作班班长 |
| opSupervisor | 操作主管 | 1:1 | 车间级（使用车间） | 使用车间主管 |
| workshopDirector | 车间主任 | 1:1 | 车间级（使用车间） | 全车间统一一人 |
| mtPersonnel | 维保人员 | 1:N | 班组级（维修班组） | 维修工，可多人 |
| mtLeader | 维保班长 | 1:1 | 班组级（维修班组） | 复用现有 `MAINTENANCE_TEAMS` |
| mtSupervisor | 维保主管 | 1:1 | 部门级（生产保障部） | 维保科室负责人 |
| mtDirector | 维保主任 | 1:1 | 部门级（生产保障部） | 维保审批最终角色 |
| archiver | 维保归档 | 1:1 | 全局级 | 归档操作人 |
| viewer | 查看权限 | 1:N | 全局级 | 默认所有人；可收窄到指定部门/角色 |

#### (3) 人员系统角色数据模型
> **职责角色即系统角色**：
> - `auth.ROLES` = **11 类系统角色**：10 职责（operator 操作人员 / opLeader 操作班长 / opSupervisor 操作主管 / workshopDirector 车间主任 / mtPersonnel 维保人员 / mtLeader 维保班长 / mtSupervisor 维保主管 / mtDirector 维保主任 / archiver 维保归档 / viewer 查看权限）+ **admin 系统管理员**。每类含 `permissions`（系统操作权限，模块→页面→动作）与 `roleKey`（步骤引擎职责标识；admin 除外）。
> - 每名人员在「人员管理」页选定**唯一系统角色**（`personnel.roleId`）；步骤引擎可执行人**直接按该角色全局派生**，不再按车间/部门层级收窄：
```
设备 D 的角色 R 的可执行人 = PERSONNEL 中 roleId === R.roleKey 的全部人员：
  resolveRolePersonnel(D)[roleKey].personnelIds = PERSONNEL.filter(p => p.roleId === roleKey).map(p => p.id)
  source = '系统角色'，sourceRef = '直接'
系统管理员 admin：不属任何 roleKey，步骤引擎特判全通过（§5.8(4)）
人员反向索引 personnelId → [roleKey...] = 该人员的唯一 roleId（驱动"我负责的设备"）
```

- **职责信息→stepPermissions 解析**：按 **角色+动作名 匹配**项目步骤（"提交/验收/确认/审核/归档"对应 §5.2 步序），**非硬套数字**；兼容 Bc/Ax 定期检查 4步vs5步 出入（以表单步序为权威）；解析校验步骤号合法；实施期逐台核对43台职责信息列一致性（§3.5，§5.10 问题8）

#### (4) 运行时步骤权限判定
```
PUT /plans/:id/step/:stepNo：
  1) 取当前登录账号 personnelId（CURRENT_USER.personnelId）
  2) 取该人员的系统角色 roleId（auth.getPersonnelById）
  3) roleId === 'admin' → 放行（系统管理员全步骤可执行）
  4) roleId === currentStep.role（step.role 即职责 roleKey）→ 放行
     否则 → 403「该步骤由角色X执行」，前端该步只读
查看权限 viewer：可只读查看设备维保单据（菜单可见性由系统操作权限 §5.8(7) 控制）
人员反向索引 personnelId → [roleKey] = 唯一系统角色 roleId：驱动"我负责的设备"
```

#### (5) 变更联动规则
| 变更 | 规则 |
|------|------|
| 人员删除/调岗 | 删除/改角色后，其步骤执行权随人员档案实时撤销（步骤引擎按 `roleId` 实时解析，无占位/转移概念） |
| 人员改系统角色 | 保存后立即生效：菜单权限（系统操作权限）与步骤执行权（`roleId` 匹配 `step.role`）同步切换 |
| 设备变更车间 | 不影响可执行人（角色全局派生，与车间/班组绑定无关） |
| 职责信息(stepPermissions)变更 | 仅影响权限矩阵，不动人员系统角色 |
| 无系统角色人员 | 不可执行任何步骤、菜单按空权限处理；在「人员管理」选定系统角色后才生效 |

### 5.9 适用范围与初始数据策略

> 维保新逻辑对**全量设备生效**（设备小类未配置标准模板的仍不生成，符合"分配了标准才有执行表单"）。

- **切换**：上线时旧 `maintenancePlans` 的**未来实例作废冻结**（不再生成/展示），历史已完成记录保留只读；避免新旧待办重复

#### (2) 存量设备资产分类：typeCode → 资产分类 默认映射表
- 新增映射表 `assetClassMap`：6位小类 typeCode → 资产分类（020101→Bc、焊机0401xx→CT、变压器0501xx→Bx…，依据 Excel §3.3 频率表）
- 解析与模板库同构（§5.7）：小类优先，未映射继承 中类→大类→全局默认（全局默认=Bc）
- 试点43台：从 Excel 逐台核对资产分类人工确认，作为首批准确数据（不靠推导）
- 接口：`GET/PUT /maintenance/config/asset-class-map`
- **不覆盖台账字段**：台账已有 `assetCategory`（A/B/CT/C1/C2，4588台全有值）——映射表**只读 `typeCode` 推导派生 `assetClass`**（含 Excel 细分 Ac/Ax/Bc/Bx/C1c/C1x），**不写回、不覆盖 `assetCategory` 字段**；同一 typeCode 台账可能跨资产分类（如 020101 同时 A=12台/B=28台），映射仅作默认，设备级可配置覆盖（配置侧）

#### (3) KPI 数据来源：班后固定表单录入 + 数采接口预留
- 日常点检"班后提交"区块为**固定表单**：说明「每日下班填写每日设备运行信息。」，人工填 **3 项**：每日运行时间（运行台时）、故障停台时间、计划停台时间
- **台时按"设备运行日历"逐日维护**（§5.10 问题3）：点检日由点检单班后顺势录；**非点检日（Bx/C1x 低频设备）由班组长/操作员补录**，避免台时缺失
- **计划停台时间**为固定表单第 3 项，**手工填写**（PRD §7.3.1 / D-06）；当日有保养/检查/润滑排期时仅提示填写，**不按额定台时自动带入**；当天有维修工单时故障停台可自动带（可改）
- 台时记录带 `meterSource: manual|auto`，中长期接 PLC/车间数采后自动填充，人工降为兜底
- 报表端按日累计计算 KPI（§5.4；利用率 = ΣR÷Σ(R+F+P)，无额定台时）

#### (4) C2(电缆)等全空频率设备：仅台账管理
- 资产分类=C2 的设备默认 **projects 全部 disabled**：不生成任何维保实例，仅台账管理
- 试点43台若含 C2 设备则按此规则；不含则全量时自动生效

#### (5) 初始数据：Excel 解析导入工具（初始化/批量导入）
- 开发一次性导入：`POST /maintenance/import/excel`
- 导入内容：设备匹配（code）+ 资产分类 + 参与项目及频率 + 职责信息（10角色人员）
- **写入目标**：全部导入**配置侧**（assetClassMap 覆盖 / projects / 职责绑定记录），**不写回台账** `assetCategory`/`person`/`area`/`typeCode` 等任何字段；导入仅按 `code` 匹配台账做存在性校验
- **模板字段逐字段核对**：按 §5.7(3) schema 与 Excel"XX标准"sheet 对齐，合并单元格/多行文本半自动解析+人工校验（首批仅020101全套）
- **职责信息解析**：按 §5.8(3) 规则转为 stepPermissions，校验步骤号合法

### 5.10 数据流转闭环核查（数据流审查结果）

> 对全链路数据流（模板→实例→执行→归档→报表；绑定→权限→签字；异常→工单→回写）的专项核查，发现并定稿 8 条修复口径。

**问题1（严重）｜人员快照 vs 实时权限冲突**
- 现象：实例生成时复制 `personnel` 快照；运行中人员系统角色变更（如车间主任换人）后，实例内旧人已无实时权限、新人又不在快照内 → 审批卡死或签字区显示旧人
- 修复口径：**权限判定按系统角色实时解析**（`personnel.roleId === step.role`，§5.8(4)），**快照仅作已签留痕展示**；待签步骤的可执行人=系统角色派生结果，已签步骤 `signer` 固定不变

**问题2（严重）｜点检异常→维修闭环缺失**
- 现象：点检异常一键报修，但维修完工后未回写点检单 → 异常项状态不更新，点检报表重复统计问题
- 修复口径：工单带 `sourceType=点检 + sourceId=点检单ID`；维修**完工归档时回写**点检异常项为"已处理"；点检报表只统计未处理异常

**问题3（严重）｜台时录入频率与点检频率不一致**
- 现象：台时随点检单班后录（仅点检日录），Bx(每周)/C1x(每月) 低频设备利用率被低估（分子只有点检日台时、分母是全月天数）
- 修复口径：**台时按"设备运行日历"逐日维护**——点检日由点检单班后顺势录，非点检日由班组长/操作员补录（或按班次一次录当日全部设备）；**利用率 = ΣR÷Σ(R+F+P)**（PRD §7.3.1，不再用「当月天数 × 额定台时」）

**问题4（中等）｜完好天数口径未定义**
- 修复口径：**当日无故障停台 = 完好日**（班后台时"故障停台=0"且当日无未处理维修工单）；完好率 = 完好日 / 当月天数

**问题5（中等）｜报表周期口径不统一**
- 修复口径：**日常点检月报按设备 02 模板该执行月整月取数**；**一级/二级保养、设备润滑月度报表按自然月（年月+车间）**；**维修汇总/问题汇总按自然月**（各自定义，标注取数边界）；完成率按**自然月归档**（§5.6 定稿口径），三张表分别标注周期，避免对不齐

**问题6（中等）｜未配置模板的空单（不兜底）**
- 修复口径：**未配置模板的小类不生成任何维保实例**（"分配了标准才有执行表单"）；不设全局默认兜底，避免"未分配却自动出单"

**问题7（中等）｜整改跟踪闭环未设计**
- 修复口径：定期检查"监控运行"问题进整改跟踪后需闭环——整改人（设备维保人员）+ 整改期限（默认15天可配）+ 复查（下次定期检查或专项复查）；整改完成→关闭；超期→催办

**问题8（核对项）｜职责信息 step 与表单步序对齐**
- 修复口径：步骤引擎以 §5.2 表单步序为权威；Excel 职责信息解析时**按 角色+动作名 匹配步骤**（非硬套数字），处理 Bc/Ax 定期检查 4步vs5步 的出入；实施期逐台核对（§5.8(3)）

### 5.11 前端承接与角色一致性核查（第二轮数据流审查）

**问题1｜步骤→页面→角色承接映射缺失**
- 现象：方案定义了各项目步骤引擎，但未写明**每步在哪个前端页面操作**，开发无法把步骤状态落到页面
- 修复：补充"步骤→页面→默认角色"承接表（默认角色为提示，运行时以设备职责信息为准，见问题2）：

| 项目 | 步骤 | 页面 | 默认角色 |
|------|------|------|---------|
| 日常点检 | 班前提交 / 班后提交 | `DailyCheckView` | 操作人员 |
| 日常点检 | 确认 / 归档 | `DailyCheckView` 步骤条 | 操作主管 / 自动 |
| 一级保养 | 提交 / 验收 / 确认 / 归档 | `LevelTaskView` 步骤条 | 操作人员 / 操作班长 / 操作主管 / 自动 |
| 二级保养 | 提交 / 验收 / 确认 / 审核 / 归档 | `LevelTaskView` 步骤条 | 维保班长 / 操作班长 / 车间主任 / 维保主任 / 自动 |
| 设备润滑 | 同二级保养 | `LevelTaskView` 步骤条 | 同二级保养 |
| 定期检查 | 提交 / 确认 / 验收 / 审核 / 归档 | `InspectionView` | 维保人员 / 操作人员 / 维保主管 / 维保主任 / 自动 |
| 设备维修 | 6步 | `RepairView` | §5.5 维修角色 |
| 设备培训 | 提交 / 确认 / 归档 | `TrainingView` | 发起人 / 操作主管 / 自动 |

**问题2｜步骤表角色 vs 职责信息10角色不一致**
- 现象：§5.2 步骤表仅列 6 角色（操作人员/操作主管/维保人员/维保主管/维保主任/归档），而职责信息有 10 角色，**操作班长/车间主任/维保班长 的步骤在步骤表未体现**（二级保养②验收=操作班长、③确认=车间主任、①提交=维保班长）
- 修复：步骤表角色列为**默认提示**，**运行时以设备职责信息 stepPermissions 判定**（§3.5 权威），不额外约束角色集；§5.2 已标注此口径

### 5.12 生命周期/日历/异常场景核查（第三轮数据流审查）

> 对"设备生命周期（新增/停用）、日历边界（停产日/节假日/维修停台）、异常场景（审批卡死/紧急超时）"的专项核查，发现并定稿 6 条修复口径。

**问题1｜步骤签名数据结构：单值 signer 无法承载多人依次提交**
- 现象：§5.1 定义 `steps[] {seq, name, role, status, signer, date}` 为单值 signer；但 §5.3(4) 已定稿"多班组轮班设备允许多人依次提交、实例记 shift 追溯"。单值字段只能保留最后一次签名，早班/中班签名丢失，留痕与权限判定均不成立
- 修复：**steps[].signatures[] 数组**（每人 {personnelId, employeeId, name, dept, roleId, roleName, 时间, shift}，**写时快照**，追加不覆盖）；步骤 status 由**完成条件**驱动而非"单次签名"——点检班前=当日当班提交齐（或班长确认）、点检班后=当班运行信息提交、其余项目步骤=1:1 角色单签 / 1:N 角色多人会签任一人签即过；实例接口返回 signatures 列表（§5.10 问题1 的"已签 signer 固定不变"对每条 signature 成立）。前端**步骤已提交内容在当前提交界面累积展示**：该步只读内容 + 其下提交人信息（姓名/工号/职务/提交时间，附备注）；提交人取当前登录人

**问题2｜班前异常停机后，班后区块仍须必录台时**
- 现象：点检单"班前异常→停机+一键报修"若让操作员认为当日点检已结束，班后区块（运行台时/故障停台时间）不提交 → 故障停台时间缺失，故障率/完好率失真
- 修复：**班前异常不阻断班后提交，班后固定表单为必录**（停机状态录 每日运行时间=0 + 故障停台时间=实际停台时长）；班后提交时自动带出该设备在途维修工单的停台时间（§5.9(3)"自动带"落地为班后提交时读工单，可改）；点检"确认"步要求班前+班后两区块均已提交

**问题3｜计划遇停产日/节假日顺延规则**
- 现象：保养/定期检查/培训的 planDate 若落在停产日/长假（春节/国庆），执行人不上班 → 计划卡死或按原日超期误判；点检虽按日历日逐日生成，但停产日如何处理未定义
- 修复：维护**停产日/节假日日历**（可配置）；保养/检查/培训实例落停产日 → **顺延至最近工作日**执行并留痕"顺延"，超期按顺延后实际执行日判定；点检停产日照常生成单（班前检查留空，由执行人按三态（正常/异常/停工）选择、不自动标记；班后台时=0），停产日无故障自然计完好日，避免停产月完好率被空单污染

**问题4｜维修停台期间到期的保养/定期检查处理**
- 现象：设备在维修工单流转中（停台），若保养/定期检查计划到期，在故障设备上执行不成立；硬执行致检查结果失真或流程冲突
- 修复：设备存在在途维修工单（未达完工/归档）时，其保养/定期检查实例**自动顺延**并标记"待设备恢复"；工单完工归档后释放执行（按完工日+宽限期判定超期，不按原 planDate 硬判）；期间点检班前区块留空（由执行人按三态（正常/异常/停工）选择，不自动标记）

**问题5｜1:1 职责角色替代**
- 现象：步骤引擎按系统角色判定可执行人（§5.8(4)）；1:1 角色（操作班长/车间主任/维保主管/维保主任）唯一人休假/出差时，对应步骤无人可签 → 流程卡死
- 修复：短期替代通过「人员管理」临时改该人员系统角色（或临时把替补人员设为该角色）；1:N 角色（操作人员/维保人员）本就多人，任一人签即过；离职/调岗在「人员管理」改角色即实时生效（§5.8(5)）

**问题6｜紧急维修 24h 补流程超时处理**
- 现象：§5.5 允许紧急维修先施工、24h 内补全流程，但超时未补的后果未定义
- 修复：24h 未补 → 工单红标"流程超时"+ 催办维保人员/班长 + 计入月度审计；超时补流程仍允许并留痕"超时补录"，归档标注超时；同一班组连续多次超时 → 升级维保主管关注
